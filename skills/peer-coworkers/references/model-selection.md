# 模型能力与选型

首次派工、任务难度明显变化或原候选不可用时读取。用户未限定模型时，按任务选择 CLI、具体模型、思考档位、速度模式和验证方式，不把品牌固定成“主脑/初级工”。本文件的模型表是可更新的选型参考，不是白名单，也不是强制路由。

## 先区分四类证据

- **官方定位**：说明设计目标与公开能力，不能当作本项目横向测试结果。
- **目录可见**：本账号的 CLI 列出了模型，不证明额度充足、请求成功或任务质量。
- **通道验收**：能接收任务、使用工具、交付完整结果并正确清理，不证明适合所有复杂工作。
- **任务实测**：在相似任务上有可复核的正确产物、耗时、修复次数与失败记录，才用于调整当地优先级。

CLI 是运行工具的入口；模型影响求解，档位影响推理预算，沙箱/工具/上下文影响执行。不能把 CLI 名称、输出长度、显示 Thought 或隐藏思考当作模型身份或思考深度证据。不同厂商的 high 不可横向等同，长上下文上限也不代表实际读完且理解正确。

## 每个工作包如何选择

1. 先明确范围、模糊程度、失败代价、所需工具与验收标准。小型强耦合工作由主代理完成；不为使用多个品牌而分包。
2. 检查已启用的 Codex、agy、Cursor 候选。复用仍适用于当前机器/版本的证据；缺少模型目录时查询该 CLI，版本或账号变化后刷新。只检查相关配置，不读取凭据，不重设全局默认。
3. 在可满足范围和权限的候选中，比较任务匹配、相似任务实测、总耗时/额度和独立性。优先考虑有清楚验收方式且成本合理的方案；CLI 熟悉程度只能解释操作成本，不能独自决定全部分工。
4. 派工前给出简短选型记录：工作包与角色 → 候选 CLI/模型/档位/速度及证据 → 本次选择与原因 → 其他候选未选原因 → 验收与升级条件。至少比较实际可用的合理替代项；仅一个候选可用时说明具体限制。无需列出全部版本或把每个候选都启动一遍。
5. 优先用当前目录的精确 ID 固定**本任务**模型，启动后核对实际显示；Auto 或继承默认可以有理由地使用，但模型/档位不可确认时写 unknown，不能当成已确认的跨模型复核。请求的 ID 与实际模型不符时先解决差异；不要让静默回退冒充原选择。
6. 若缺证据、越界或未通过验收，先判断是任务说明/环境问题还是求解不足。明确剩余问题后，在现有修复轮次与预算内缩小工作包、提高已支持档位或换适合的候选；不因第一次网络失败就宣布模型能力不足，也不无限重复同一提示。

选型说明可以很短：“实现者为已确认的 GPT 模型；本轮复核比较 Cursor/Grok 4.7 与 agy/Sonnet 4.6，选择前者做跨文件反例分析，后者保留为额度不足时的候选。目标档位 high，启动后确认；按可复现缺陷验收。”这是格式示例，不是默认组合。没有查到额度、速度或模型身份时，不编造未选原因。

## 思考档位与当前脚本边界

### 默认不用 Fast

这是用户的日常偏好，不是模型能力结论：**默认标准速度，只有用户当次明确要求才启用 Fast。** “尽快完成”等一般时效要求不自动授权开启 Fast，也不把“标准速度”解释为必须使用低思考档。

- 目录存在标准与 Fast 变体时，默认选择标准变体。例如当前目录中的 `grok-4.7-high`，而非对应的 Fast 变体；使用精确 ID，不自行拼接后缀。
- 某些入口可能把速度作为独立会话设置。启动后、提交任务前核对模型与速度；只有确认设置仅影响本会话时才关闭 Fast。不能从 `--model`、无 fast 后缀或另一会话推断实际速度。
- Auto 或继承 CLI 默认也遵守此偏好。无法确认速度时记录 unknown，先尝试当前入口的只读配置/界面检查或其他可确认的标准模式候选；仍无法确认就明确报告限制，不把未知当作已关闭，也不静默提交该候选的任务。
- Gemini **Flash** 是模型系列名称；Luna、Haiku 或其他模型“速度快”的定位也不是 Fast 开关，不因这项偏好排除它们。Fast 与思考深度、模型质量分别判断。
- 本规则由主代理选型和会话核对执行；当前脚本没有通用 `--fast` / `--no-fast` 控制，也没有对 Fast ID 作硬性封锁。目录快照保留 Fast 条目用于完整记录，不代表默认允许选择。不得为落实偏好改写持久的全局 CLI 配置。

### 按任务选择思考档位

| 工作特征 | 起点与调整方式 |
|---|---|
| 目标清楚、局部、可自动判定 | 使用该模型已确认的默认或较低档位；先看正确率与返工成本。 |
| 跨文件推理、反例、契约冲突、难复现问题 | 比较适合模型的 medium/high；推理不足时再考虑更高档位或模型。 |
| 最大档位 | 仅当难度、时间与额度允许且有收益时考虑；不要默认全部 max。 |

2026-10-21 的实际目录显示：agy Gemini 3.8 Flash 有 low/medium/high；Cursor Grok 4.7 有 low/medium/high/xhigh，各有 Fast 变体。Fast 是速度选项，不能当作更深思考。agy 的 Claude ID 标了 Thinking，但未给出实际 effort，记录为 unknown；不从名字推算 high。

Codex 缓存列出 low/medium/high/xhigh/max，部分模型还有 ultra。缓存和官方说明均指出 ultra 涉及自动分派；本技能不允许工作进程再次分派，因此不为工作进程选择 ultra。一般调高思考与新增工作进程是不同决策。Codex 的进一步说明按 [OpenAI Docs](https://learn.chatgpt.com/docs/models) 核对；当前档位不能由另一会话或主代理设置推定。

当前 `cowork.py` 只支持 `init --model MODEL_ID`，没有 `--effort`，且不接受 Cursor 的方括号参数化表达式。使用实时目录提供的完整 ID，例如 `grok-4.7-high`、`gemini-3.8-flash-high`；不要自己拼出不存在的后缀。若档位不在 ID 中，只能在已确认仅影响本会话的模型菜单中选择并读屏核实；无法可靠确认就保留 unknown，不为此修改全局配置或假装支持新参数。

## 独立性与最小校验

独立上下文、不同模型家族和不同工具环境是不同维度。实现者与审查者换了 CLI，却仍使用同一模型，只能报告上下文/工具差异；同家族不同型号也不能宣称厂商视角完全独立。需要交叉审查时优先选择胜任的另一家族，不要求每个任务都覆盖三家。

给复核者原始需求、固定版本的产物与验收条件，先收集其独立判断，再比较结论。新候选可以先承担一个有界工作包，同时完成通道与任务验证，无需先跑一套庞大基准。依据可定位缺陷、复现/测试和范围遵守来接受；长篇答案、零发现、算术成功或多数模型同意都不能替代这些证据。

质量试用记录至少包含：日期/环境、CLI 版本、请求模型与实际模型/档位/速度模式、工作包类型与固定输入、验收结果、缺陷/遗漏、耗时及可获取的用量、修复轮次。区分“未测试”“通道失败”“质量不合格”。相同输入与标准下的观察才支持调整优先级；一次胜负不建立永久等级。
