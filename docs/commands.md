# Command reference

All commands use `python3 skills/peer-coworkers/scripts/cowork.py`. Commands return JSON and exit 0 for successfully reported outcomes; errors exit 1 and argument errors exit 2. A reported timeout or unknown capability is an observation, not a successful work package.

| Command | Parameters and behavior |
| --- | --- |
| `doctor` | Find executables and versions; compare each enabled profile to its latest probe. Does not execute the disabled profile. `--probe --profile P [--no-proxy]` additionally runs the live behavioral probe, including actual sandbox writing and actual pane proxy-environment comparison. |
| `init` | `--cwd ABS --goal TEXT --role implement/test/review/research --acceptance TEXT` (repeatable); write roles need repeatable `--owned-path`. Optional `--profile`, `--model`, `--runs-dir`, `--budget-seconds` (600), `--max-replies` (2), `--enable-opencode`. Creates a private prompt, task record and baseline. |
| `start` | `--run RUN [--no-proxy | --proxy-url URL]`. Single launch attempt; persistent workspace lease checks prevent incompatible concurrent use. Confirmed dead sessions are reclaimed and reported. Unknown leases remain blocking. |
| `show` | `--run RUN`. Task metadata without large snapshots. |
| `screen` | `--run RUN`. Verify exact owner/task/cwd/pane and capture current screen. |
| `paste` | `--run RUN [--multiline-verified EVIDENCE]`. Single attempt to paste the short task-file pointer, with no Enter. |
| `submit` | `--run RUN --received-confirmed [--timeout-ms N]`. Persist uncertainty, send one Enter, observe up to 20 seconds. Never retries. |
| `observe` | `--run RUN [--timeout-ms N]`. Resume the existing terminal observation; no Enter. Shares approval and busy patterns with `wait`. Budget-limited. |
| `wait` | `--run RUN [--timeout-ms N]`. Default/max 25 seconds. Returns `result_ready`, `question`, `approval`, `exited`, `attention`, or `timeout`. JSON must be valid for this task, attempt and round and remain stable for 120 ms. This read operation remains available after execution budget exhaustion. |
| `keys` | `--run RUN --key K` (repeatable). Allowlisted terminal keys, logged as uncertain before sending and sent afterward. Enter, C-j and C-m are excluded. Use only for a specific authorized interaction. |
| `cancel` | `--run RUN [--timeout-ms N]` (default 2000, max 5000). Requires a passing cancellation check for the current executable/version. Sends one Escape; only explicit stopped evidence or pane exit confirms cancellation. Repeated calls while cancelling observe without another Escape. Otherwise use explicit close. |
| `reply` | `--run RUN --message-file F`. Bounded regular UTF-8 file, at most 32 KiB. Archive old result/question, increment round, create private reply file, paste a short pointer, require its literal display, then submit once. Uncertain failures cannot be retried. |
| `collect` | `--run RUN`. Validate current result and scope/Git state. DONE awaits independent acceptance; PARTIAL/BLOCKED retain concrete remaining work. |
| `accept` | `--run RUN --evidence TEXT`. Revalidate current result and artifacts against collection. |
| `close` | `--run RUN [--allow-active]`. Acquire workspace lock before cleanup. Refuse owner/task/cwd/pane mismatches. Confirmed missing session releases the lease and reports `session_gone`. Retry lease release if unlink failed after cleanup. |
| `reap` | Scan persistent leases and report active/gone/unknown. Reclaim confirmed gone sessions. Missing/corrupt task records and unconfirmed launches require exact `--task ID --force`; force never removes a confirmed active lease. |
| `probe` | `--profile P [--model M] [--cwd ABS] [--timeout-ms N] [--budget-seconds N] [--no-proxy | --proxy-url URL]`. Nine independent real interactive checks; default 25 seconds per check, 240 total. Cleanup/diagnostic reads have separate bounded overhead. Store a dated/versioned JSON report in the state directory and raw evidence in the private runs directory. May incur CLI usage. No approvals are answered. |
| `term` | `screen`, `history`, `status`, `paste`, `submit`, `wait`, `keys`, all with `--run RUN`. Task-bound forwarding; shared submission and intervention rules. `history` captures scrollback using `-S -`. |

Probe covers readiness, literal paste, computed single-line response, multiline receipt and response, one-Escape interruption of a real heartbeat command, anchored approval recognition, atomic nonce-file writing, 150-line history recovery, and precise cleanup with a same-server sentinel. Each check gets its own marked session. A failed check does not prevent later checks. Exceeding the total budget records the remaining checks as timeouts. Literal receipt, filesystem content and process behavior are required; a quiet screen is insufficient. Probe results are capabilities, not task acceptance.

Configuration: `${XDG_CONFIG_HOME:-~/.config}/peer-coworkers/config.json`; `PEER_CONFIG` selects a different JSON file. `proxy.mode` is auto/command/url/off, `proxy.command` is trusted local Bash code for command mode, and `proxy.url` is an HTTP(S) endpoint without credentials. `--proxy-url` selects URL mode for that launch; `--no-proxy` disables internal setup. A command failure prevents launch. Proxy variables removed by the command are removed from the worker environment too; the caller's environment is restored after launch. The task stores mode, command result and configured URL, never shell output or proxy credentials.

`runs_dir` overrides temporary storage. Persistent leases and probe reports use `${XDG_STATE_HOME:-~/.local/state}/peer-coworkers`. `profiles.PROFILE` can override absolute `path`, default `model`, `approval_patterns`, `prompt_lines`, `cancel_lines`, and `busy_regex`. Explicit approval patterns are user-selected recognizers and do not imply verified compatibility. Otherwise only a passing, matching probe supplies normal approval recognition. Probe candidate patterns are separately identified and tested. `snapshot.max_files` defaults to 50000; `snapshot.max_bytes` defaults to 268435456. `snapshot.max_record_bytes` defaults to 67108864 (64 MiB) for task metadata including both snapshots. Record reads and atomic writes share this bound; an oversized update preserves the previous readable record. Very long paths or larger configured workspaces can require raising it. Result and question files retain their separate 16 KiB limits. Exceeding a limit reports the configuration key to adjust.
